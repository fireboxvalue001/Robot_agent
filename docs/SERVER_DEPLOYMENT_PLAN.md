# 公网部署计划与进度台账

更新日期：2026-10-27（北京时间）

## 1. 目标与边界

- 本地和服务器各保留一套可独立运行的项目，本地继续使用原有启动方式。
- 国内个位数用户通过 HTTPS 使用网页、ASR、委托单、能力查询和 AI 编排。
- 通过现有接口及 MQTT 与同事模块、实验室机器人和仪器联调。
- 代码通过明确的发布流程更新到服务器，用户无需安装客户端。
- 第一版不做账号登录或用户数据隔离，采用共享工作空间，但必须区分任务和设备占用。
- 不修改本机系统环境，不搬走或覆盖本地项目，不把 Windows .venv 上传服务器。
- 网页部署不等于设备执行接口已实现；AI 编排通过不等于允许物理执行。
- 本计划是待实施方案，文中部署文件、保护措施和接口改造不能视为已经存在。

## 4. 目标架构

```text
本地项目 -- 测试 / Git 版本发布 --> 服务器独立副本
                                    |
用户浏览器 -- HTTPS --> Caddy --> FastAPI（网页和 API）
                                    |-- 云端 AI / ASR
                                    |-- 持久任务记录 / 通信历史
                                    |-- MQTT Broker --> 实验室网关 / 同事模块 --> 设备
```

Caddy 和应用由 Docker Compose 管理。应用首版使用单进程，后端端口不直接开放公网。数据库、历史、密钥、证书和备份与发布代码分开保存。继续使用现有 Broker 的前提是其连通性、认证、TLS 和主题权限适合部署需求。

## 6. 发布与回退约束

- 开发期间不在服务器直接随意修改业务代码；部署必须对应明确的提交或发布版本。
- 首版允许短暂维护：停止接收新任务，等待在途请求结束或明确终止，再替换服务。
- 物理任务不能因为网页重连、服务重启或回滚而重复下发；恢复时先与设备侧核对。
- 代码回退不自动回退数据库；有数据结构变更时，先验证向后兼容和备份恢复。
- 服务器和本地可使用相同代码但不共享运行数据；共用云 API 凭证会共享额度及限流。
- 若旧 Git 历史曾包含真实密钥，迁移前评估并轮换；只删除当前文件不能消除历史泄露。
