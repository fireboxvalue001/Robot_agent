# 皮革油脂抽提场景接入说明

本场景依据用户提供的《油脂提取实验流程.docx》建立皮革二氯甲烷索氏抽提的逻辑流程。当前可生成带参数来源、条件分支、恒重循环及结果引用的草案；不执行真实设备，不生成测量结果。检测结果名称使用“干基二氯甲烷可溶性抽提物含量”，不将所有抽提物直接等同于纯油脂。

场景配置0.3.0已迁移到通用条件编排器，阶段分组、展示说明及方法待确认项均在JSON内定义；不再使用油脂专用前端分组。通用接入说明见 `docs/CONFIGURED_WORKFLOWS.md`。

## 界面使用

1. 启动项目后刷新浏览器，在“本地编排方式”中选择“AI智能编排”。
2. 输入：`对皮革样品进行二氯甲烷索氏油脂抽提，按照实验文档及补充方案完成水分测定、容器恒重、至少30次完整回流、蒸馏冷凝回收以及干基含量计算。`
3. 点击“生成实验流程”。系统显示阶段流程图；恒重阶段包含通过与重复分支。展开阶段可查看独立动作、参数来源、数据引用及异常退出。
4. C1下方“本次需要补充什么”默认收起并显示待处理数量，点击可展开或收起。展开后展示全部待补项：中文名称、单位、用途、填写框及文字格式。可以分批填写，点击“应用已填写项并重新编排”；已解决的项目移出清单，空白项目继续保留。也可以继续使用“补充任务信息”文字输入。不得用猜测值消除缺失提示。
5. 方法审核、输入冲突或AI服务错误单独列为其他待处理项。当前用户已补充蒸馏冷凝回收方法，不再询问“具体怎样去除”；只列设备、运行条件、观察确认方式和适用标准等剩余确认事项。

以上指令仅用于查看草案，不是完整实验操作指令。最新补充明确以至少30次完整回流作为正常结束门槛；原文7～8h保留为参考，标准是否同时要求最短持续时间需负责人确认，不按时间推算循环次数。“抽提最长允许时长”仅是异常超时保护，须另行确认，不用来替代次数门槛。没有配置AI服务时会明确报告错误，不会暗中切换离线模式。

## 参数与来源

场景配置文件 `knowledge/planner_scenarios/leather_extraction.json` 保存参数定义、文档引用和单步流程。文档明确给出的切块边长、称量瓶105℃、首次6h、重复1h、冷却30min、称量瓶5mg及约5g取样目标附带原文来源。取样目标不代替实际称量值。

空抽提瓶的具体干燥条件、最终抽提物的干燥条件、最终恒重阈值等不从称量瓶参数自动推断。7～8h是范围，不自动选取固定时长。

用户可按“标签：数值单位”填写；数值需先确认。所有必填标签与单位可通过知识接口查询，主要包括：

| 标签 | 单位 |
| --- | --- |
| 水分测定干燥温度、水分测定干燥时长 | ℃、min |
| 空抽提瓶干燥温度、首次干燥时长、重复干燥时长 | ℃、min、min；标签分别使用完整的“空抽提瓶…”前缀 |
| 空抽提瓶恒重阈值、最终恒重阈值 | mg |
| 二氯甲烷用量 | mL |
| 抽提水浴温度、抽提最长允许时长、回流检查间隔 | ℃、h、min |
| 最低回流循环次数（用户补充默认30次，不得降低） | 次 |
| 蒸馏回收加热温度 | ℃ |
| 允许拆卸温度上限、冷却最长等待时长 | ℃、min |
| 恒重最大循环次数、剪切最大次数 | 次 |
| 抽提物干燥温度、抽提物干燥时长 | ℃、min |
| 溶剂去除最长时长 | min |

数值范围仅是输入合法性边界，不是设备额定范围或实验安全建议。首次使用必须审核具体实验方法、化学相容性和设备条件。

AI提取值必须带用户原文中的连续片段、数字和同单位证据；程序检查数值、单位、所属阶段及与明确标签的一致性。无来源值、不同值冲突、非有限值或模型错误均阻止通过。明确标签出现矛盾时，需要修改原文，不能靠追加另一数值覆盖。

## 能力与资源

版本1.7.0能力库增加29个单步接口，总计93个兼容条目：55个单节点条目、38个历史组合。新增16个机器人操作、12个仪器操作和1个环境检查，均为 `interface_only`。抓取、移动、释放、吸液和排液复用现有能力。天平读数归机器人类，仪器类按天平、烘箱、水浴、冷凝水、溶剂去除设备分组。

当前能力库1.7.1将回流监测接口升级为1.1.0，新增 `completed_cycles` 非负整数反馈。调用方必须重新读取版本和摘要。场景版本0.2.0增加30次门槛、蒸馏回收步骤及独立的超时保护，不再以旧7～8h计时作为自动完成条件。

资源文件 `data/leather-extraction-resources.json` 保存设备与位置绑定。初始设备、位置、控制配置均为空；不虚构现场坐标。后续位置应引用现有 `data/spatial-locations.json` 中经登记验证的位置ID。

当前已登记 `dcm_distillation_recovery_v1`（蒸馏冷凝回收）为用户提供方案草案，场景默认引用，不需要用户再猜方法ID。保留四步原意：至少30次完整回流后停热、冷却拆卸，取下抽提器与滤纸筒，将保留萃取液的抽提瓶接入通风橱内蒸馏冷凝回收装置，受控加热并冷凝回收，观察蒸馏阶段结束后再进入标准要求的后处理。

“无持续馏出液”且“无明显大量游离溶剂”只作为操作性结束参考，不证明无残留、不替代残留检查或恒重。流程仍保留冷却、残留检查、按标准烘干、冷却和称量。方法标为 `draft`，设备型号、加热条件、监测与确认方式、适用标准仍待确认；用户补充不自动授权执行。明确指定其他ID时，不会悄悄替换回默认方法。

## 本地接口

### 查询场景

`GET /api/planner/knowledge?scenario_id=leather_fat_extraction`

返回能力库身份、场景版本、参数定义和完整步骤模板。`GET /api/planner/status` 的 `scenarios` 同时包含此场景；原有两个场景不变。

### 请求编排

```json
{
  "scenario_id": "leather_fat_extraction",
  "knowledge_mode": "demo",
  "model_mode": "deepseek",
  "text": "对皮革样品进行二氯甲烷索氏油脂抽提，至少30次完整回流后按补充方案蒸馏冷凝回收。"
}
```

发送至 `POST /api/planner/plan`。`knowledge_mode=demo` 表示允许生成尚未完成方法审核的逻辑草案，不代表真实运行。`approved_only` 会返回需要审核。

响应沿用本地规划结果，额外包含 `workflow_definition`；旧场景该字段为null。完整条件流程的约束见 `schemas/conditional-workflow.schema.json`。关键字段包括：

- `contract_version`：独立本地条件流程版本1.0.0。
- `nodes`：唯一节点ID、操作ID、参数引用、结果引用及分支。
- `next`：顺序后继；`on_pass/on_fail`：判断分支。
- `on_error/on_timeout/on_limit`：异常、超时、次数上限出口。
- `previous_state_ref/repeat_state_updates/counter_id`：恒重循环状态更新及独立计数器。
- `parameters`：值、单位、原文来源；`resources`：待绑定资源。

同一操作ID可在不同节点重复出现。实际调用参数使用 `parameter_ref/resource_ref/object_ref/method_ref` 绑定，不把引用字符串当成已获取的测量值。对象引用需要后续绑定具体瓶子、工具、槽位和接口；资源绑定未完成不影响查看逻辑草案，但禁止执行。

当前并未增加硬件流程运行器或长时任务调度器；节点的等待、轮询、状态更新和异常出口是交接定义。物理执行模块接入时，必须实现这些语义及相应反馈，不得把它们降级为单纯延时。现有MQTT topic、字段和线性 `operationChain` 规范均未修改，也不会向该协议伪装发送循环流程。

### 校验测量数据

`POST /api/planner/leather-extraction/evaluate` 只校验调用方提供的数据，不采集测量值、不操作设备。

```json
{
  "calculation": "constant_mass",
  "values": {
    "previous_g": 10,
    "current_g": 10.004,
    "threshold_mg": 5,
    "iteration": 1,
    "max_cycles": 3
  }
}
```

此处数字仅为软件测试数据。恒重严格使用质量差小于阈值；等于阈值继续循环，达到上限返回 `limit`。另外支持 `moisture`（`container_g/wet_total_g/dry_total_g`）和 `extractable_content`（`empty_g/final_g/sample_g/moisture_fraction`）。水分比例单位为0～1，不是百分数。结果计算拒绝负增量、零干重、非有限值及抽提物质量大于样品干重的数据。

## 检查范围

程序检查操作ID、唯一节点ID、分支目标、节点可达性、结果字段引用、引用是否在所有前置路径上可用、恒重循环上限、参数来源及范围。它不证明化学方法适用、传感反馈真实、空间可达或设备安全。

测试命令：`python -m unittest tests.test_extraction_planner`；另运行原有全套后端测试、前端冒烟测试及能力库结构检查。无需安装新增依赖。
