# 配置化实验流程与通用可视化

本次将流程图、待补信息和条件流程校验统一为配置驱动框架。油脂提取与新增“样品定时静置”使用同一编排器和前端组件。VD10、定量移液保留原有线性规划适配器，通过同一场景目录发现和选择；不改已有MQTT消息协议。

这不是任意实验的自动发现系统。新增场景仍需要明确的方法、已登记的能力和流程配置；AI主要提取参数和识别未覆盖要求，不自行发明实验方法。

## 配置文件

| 文件 | 用途 |
| --- | --- |
| `knowledge/planner_scenarios/registry.json` | 场景ID、名称、配置文件、编排引擎、识别模式及界面选项 |
| `schemas/process-scenario.schema.json` | 场景参数、阶段、步骤及方法要求的配置约束 |
| `knowledge/planner_scenarios/leather_extraction.json` | 油脂提取场景，含恒重、回流次数、蒸馏回收与方法确认 |
| `knowledge/planner_scenarios/sample_hold.json` | 跨场景示例：样品放置和定时静置，支持数字、文字、选项和是/否输入 |
| `schemas/conditional-workflow.schema.json` | 通用条件流程输出约束，不再固定某个实验ID |
| `data/meta-operations.json` | 所有场景共享的唯一能力库 |

`backend/planner/build_extraction_data.py` 是油脂场景的维护工具，不参与请求时的通用编排。手工修改生成的油脂配置后，不应运行它覆盖修改；新增场景不需要修改或运行这个脚本。

## 界面测试

1. 选择“AI智能编排”。“智能规划选项”中的场景列表从服务端目录加载，可自动识别，也可明确选择。
2. 输入“样品定时静置”，生成流程。应显示样品放置、定时静置两个阶段，不出现恒重、回流或蒸馏内容。
3. 展开待补清单，填写样品标识、静置位置、静置时长、存放方式及是否核对。可以分批提交。
4. 软件测试可使用样品标识S-01、位置“暂存点A”、30秒、遮光、已核对。这些只验证数据绑定，不代表现场位置存在或可以执行。
5. 查看逻辑计划结果，执行仍被禁止，物理条件保持待确认。

浏览器自动化检查使用明确选择的离线模式，不调用真实云端模型。正式测试AI时须配置现有模型服务；系统不在失败后隐式降级。

界面现仅有“本地规则编排（离线）”与“AI智能编排”。本地入口可直接使用条件流程配置；旧关键词能力也保留于该入口。手动指定已登记场景可进行确定性模板校验，不需要第三个离线选项。

## 接入一个新场景

1. 复制 `sample_hold.json`，修改唯一的 `scenario_id`、名称、知识ID和来源。场景步骤必须对应已有能力；缺少的单步能力先登记到能力库。
2. 在 `parameters` 中定义中文标签、类型、单位、必填状态、数值范围或选项。支持 `number`、`string`、`boolean`；数字可指定 `integer`，各类型可指定同类型的 `enum`。默认值必须带明确来源。
3. 在 `phases` 中定义阶段ID、中文名称和可选图示说明。每个节点通过 `phase_id` 指向阶段，不按节点名称或ID前缀猜测分组。异常阶段用 `exception=true` 标记。
4. 在 `nodes` 中定义唯一节点ID、类型、能力ID、所需参数、输入绑定、结果引用及分支。动作通过 `operation_id` 引用能力，组合流程不是一个元操作。
5. 在目录JSON中新增一项，指定 `engine=conditional` 和配置文件。配置文件须位于项目的 `knowledge/planner_scenarios` 目录；资源文件须位于 `data` 目录，不接受请求传入任意路径。
6. 重新请求场景目录或刷新界面，即可选择新场景；支持的节点和参数类型不需要新增Python分发分支或专用前端代码。

目录项示例：

```json
{
  "id": "my_experiment",
  "name": "新的实验场景",
  "engine": "conditional",
  "file": "knowledge/planner_scenarios/my_experiment.json",
  "enabled": true,
  "routing_patterns": ["明确的场景识别词"],
  "ui": {"handoff_required": false, "parameter_mode": "process"}
}
```

自动识别只在恰好匹配一个登记场景时选择。未知目标或多个匹配都要求用户明确选择，不自动回落VD10，也不把多个场景拼接起来。

## 流程与展示语义

- `next` 是顺序后继；`on_pass/on_fail` 是判断分支；`on_error/on_timeout/on_limit` 是异常出口。
- 同一能力可由不同节点ID重复调用；`max_iterations_ref` 必须引用必填的正整数参数，重复分支须有上限出口。
- `input_bindings` 支持 `parameter_ref`、`resource_ref`、`object_ref`、`method_ref` 和常量 `value`。引用不代表已取得物理数据。
- `data_refs` 指向前面节点声明的输出。校验分支、可达性及引用是否在所有前置路径上可用。
- `display.notice` 和 `display.branch_labels` 保存节点的用户说明；阶段的 `diagram` 保存判断说明、重复分支文字、上限引用等。`{{参数名}}` 只做文字替换，不执行表达式。
- 阶段图的跨阶段连接读取实际节点分支，不盲目把配置列表顺序当作流程；同阶段细节见展开后的单步列表。异常出口单独标识。
- 待补清单根据参数缺失、方法确认和校验问题统一产生，默认收起。填值前检查类型和范围，再与原文合并重新编排，不自动覆盖冲突。

`required=false` 的参数若仍被某个节点列入 `requires`，该节点依然需要它；不能通过将全局字段改为可选来跳过动作输入。

## 方法与资源

场景可不需要额外方法登记，也可用 `method_requirements` 定义一个或多个要求。配置选择标签、默认方法ID、资源集合和适用约束；用户说明、剩余确认项及审核提示均来自配置。方法已说明不等于已审核，文字中的“已批准”不修改登记状态。

设备、控制配置及真实位置仍由独立物理确认模块负责。配置驱动编排没有增加硬件流程运行器，也不会把循环降级为线性MQTT操作链。

## 接口

- `GET /api/planner/scenarios`：读取可用场景名称、引擎及界面选项。
- `POST /api/planner/resolve`：输入 `text`、`scenario_id`（默认`auto`），返回已选场景或需要选择的候选。
- `GET /api/planner/knowledge?scenario_id=...`：查询指定场景配置及能力库摘要。
- `POST /api/planner/plan`：显式指定场景，或设置 `scenario_id=auto`；条件场景返回 `workflow_definition`、统一校验说明和待补清单。

现有线性请求不指定场景时继续保留VD10默认值以兼容调用方；新界面先进行显式场景解析。未知或歧义的自动请求返回422，需要用户选择。

## 仍需代码扩展的部分

新增实验若只使用已有动作、参数类型、分支和循环结构，主要增加JSON。新增硬件能力、全新的节点语义、传感反馈处理或计算算法仍须实现并测试对应代码。计算名称只允许已注册算法，不执行配置中的任意Python、JavaScript或数学表达式。

油脂专用的恒重、水分和干基含量计算仍保留为已登记的领域函数，而不是假称对所有实验通用。VD10和定量移液的既有线性适配器也没有被本次重写。
