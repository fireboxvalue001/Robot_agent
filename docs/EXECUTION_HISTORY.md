# 本地执行档案与预留执行接口

## 已实现范围

C4底部“本地执行档案”默认收起。生成流程、修改流程或更新现有演示记录后，页面等待500ms自动归档；也可点击“保存当前记录”。成功写入后显示“已归档”，失败明确提示重试。页面刚生成后请等待保存成功再关闭浏览器；尚在等待或网络失败的内容不保证落盘。

历史列表支持分页，每条记录提供“查看记录”和“导出 JSON”按钮，无需进入详情即可导出；详情也保留导出按钮。刷新网页或重启后端后可以重新查看历史；清空当前流程不会删除历史。历史为只读，不覆盖当前任务，不恢复设备运行。每次内容改变保存不可变快照，相同内容去重，不等于新建一次物理执行。列表时间是服务器归档时间，记录内的操作时间保留原有时区。

保存内容包含任务标识、输入文本、能力库身份、流程定义、推理说明、每步状态、起止时间、耗时、关键数据和结构化结果。条件流程保留完整图、参数和分支；尚未运行的节点时间为空，结果为空。不会将循环图转换为线性MQTT命令。

目前仅接受 `plan_draft`（未执行草案）和 `simulation`（演示记录），不接受真实成功、运行中或硬件事件。现有前端演示时间不是设备测量时间；归档不改变其性质。真实执行接口接入后需要独立的runId、循环attempt、事件去重、状态迁移和鉴权，不可把草案或演示数据改名当作实机记录。

## 存储

默认路径：`data/execution_history/history.sqlite3`。使用Python标准库SQLite，无新增依赖。表 `archives` 保存不可变完整快照，`step_records` 保存逐步记录，二者在同一事务内提交。参数化查询，重复快照通过SHA-256去重。数据库文件已排除Git跟踪。

可用后端环境变量 `EXECUTION_HISTORY_DB` 指定专用持久化文件路径，容器部署时须挂载对应目录。备份建议停止后端后复制数据库，或使用SQLite备份接口；不要在写入期间随意复制数据库。当前不自动清理历史，不保存音频；文本、样品信息及测量信息可能敏感，应限制后端访问及备份权限。沿用当前项目的访问边界，本接口未新增用户鉴权，公开部署前必须由网关或后端补齐访问控制。

## 接口

| 方法与路径 | 功能 |
| --- | --- |
| `POST /api/execution/archives` | 保存快照，返回archive_id、created_at、deduplicated |
| `GET /api/execution/archives?task_id=...&limit=20&offset=0` | 列表及total，task_id可选，limit最大100 |
| `GET /api/execution/archives/{archive_id}` | 完整只读快照，未知ID返回404 |
| `GET /api/execution/capabilities` | 归档能力和设备接口启用状态 |
| `POST /api/execution/submit` | 预留计划提交，当前返回501 |
| `POST /api/execution/events` | 预留真实设备事件，当前返回501 |
| `POST /api/execution/control` | 预留执行控制，当前返回501 |

归档请求字段：`task_id`、`source_text`、`kind`（linear/conditional）、`record_source`、`plan`、`execution_run`、`execution_records`、`structured_result`。未知顶层字段拒绝。单条JSON最大5MiB，最多5000步；步骤ID非空且唯一，时间须包含时区，结束不能早于开始。单条快照代表一次存档版本，而不是完整的硬件事件流。

响应中的 `execution_allowed` 始终为false。归档接口不是计划提交接口。预留接口尚未约定设备消息体，未来应与设备同事协商后单独制定版本，不复用归档请求控制硬件。现有上游MQTT topic、字段及通信历史规范未改变。

## 界面验证

1. 启动更新后的后端并刷新页面，生成一个油脂提取或其他流程。
2. 展开C4的“本地执行档案”，确认显示“已归档”，列表中新增“流程草案，未执行”。
3. 点击条目查看节点、空时间和完整参数；导出JSON检查分支保留。
4. 刷新页面或重启后端，再次展开档案，旧记录仍可查看。
5. 清空当前流程，确认历史仍在；查看历史不会启动执行或修改当前输入。
