# VD10屏幕场景与C2来源

## 设计依据

遵循META_OPERATION_SPEC和META_OPERATION_HANDOFF：`data/meta-operations.json`为唯一能力库；C3动作必须引用C2现有ID和版本，场景文件仅组合能力和绑定参数，不定义机械臂动作。判断、开始、结束属于流程控制，不是元操作。

原能力库已有机械臂触摸屏操作、面板按键轻按、屏幕读取。触摸屏能力内部已经包含定位、触碰和验证三个节点。本次优先复用原有条目，不假定面板实体按键与触摸屏等价，也不把持物搬运冒充机械臂空载接近动作。

前几轮临时增加的九项`robot.meta.vd10_screen_*`接口已从当前能力库移除。这些接口尚未提交交付且没有驱动；历史档案保留原始快照，不迁移成新ID或重放执行。原有93项能力的ID、输入输出及内部节点未更改，库版本更新为1.8.2以标识此次能力集变更。

## 四个场景实际引用

| 场景 | C3动作所引用的C2能力 |
| --- | --- |
| 测试信息填写 | `vd10.meta.prepare_test` |
| 历史结果查询 | `vd10.meta.query_test_results` → `robot.meta.read_result_from_screen` |
| 质量状态查看 | `vd10.meta.inspect_quality_status` → `robot.meta.read_result_from_screen` |
| 机械臂触屏查看质量状态 | `robot.meta.operate_touchscreen` → 同一能力的第二次调用 → `robot.meta.read_result_from_screen` |

机械臂场景的两次调用分别绑定原说明书节点`vd10.menu.enter_quality`和`vd10.quality.open_status`。它们是目标控件引用，不是已识别到的按钮或已标定坐标。两次调用具有不同step_id，不修改C2能力ID。触屏返回action_verified后经独立判断节点确认，再进入后续步骤；无真实反馈则不具备继续执行依据。

显示分别使用“进入质量菜单”和“打开质量状态”，并注明使用能力为“机械臂触摸屏操作”。这是调用层说明，不是重命名C2能力。标题模板、对象参数和复用约定见`docs/OPERATION_CALL_DISPLAY.md`。

原触屏、结果查询等条目仍为历史组合，C3和C2都明确显示此标签。可展开查看C2原有内部节点，但这些节点不是额外独立元操作。若要完全单步化，应先审核原内部节点的输入、输出和控制接口，再批准拆分；本次不伪造这些接口。

## 界面对应关系

C3顶部只提供可视化流程说明，分支、循环和检查在此表达。下面的流程编排和物理确认恢复原有操作卡片风格：操作从C2读取，可由左侧点击或拖入，支持拖动排序和移除；物理确认区同步展示对应操作卡片。开始、结束和判断节点不加入下方操作卡片。后台仍返回capability_ref以及reasoning_trace.mappings，记录实际能力库版本、校验摘要和操作引用。

条件流程的下方卡片是编辑视图，不是将分支、循环扁平化后的执行指令。手动修改时顶部原图保留为参考并提示过期，逻辑及物理通过状态失效，需要重新编排校验；编辑视图不能提交执行。归档额外保存plan.editor_projection中的编辑顺序和dirty状态，同时保留完整原始流程定义，不将其伪装成线性MQTT操作链。

动作无operation_id、ID不存在、停用或版本不一致时不能通过校验。C3也核对当前左侧能力版本，防止旧缓存被显示为正常匹配。参数、真实设备绑定、物理确认和驱动实现仍是独立要求，来源匹配不代表实机可执行。

选择AI智能编排，或明确选择本地规则编排验证模板。更新后端后强制刷新页面。


```text

```

```text

```

```text
VD10机械臂触屏查看质量状态
```

检查C3每张操作卡片对应的ID是否在左侧存在。机械臂场景应出现两次“机械臂触摸屏操作”和一次“非联网仪器屏幕数据读取”，而不是新生成的接近、触碰、撤离能力。在左侧能力详情可查看原有定位、触碰、验证节点。拖动排序、删除卡片或从左侧添加后，物理确认区应同步更新，顶部原图提示需要重新校验。

缺少样品编号时显示待补项。所有场景禁止真实执行；不启动检测、不删除、不校准、不退出。只读`GET /api/v1/capabilities/vd10-screen`返回C2引用清单和定位占位，不是另一份能力库或执行接口。

## AI与模板的真实边界

这些屏幕场景沿用通用条件编排器，组合由已登记场景规定，AI负责提取参数及报告未覆盖要求。它们没有升级成任意C2操作的自动搜索规划器。原VD10线性AI规划仍从检索到的C2候选选择并校验，未在本次改写。既有MQTT规范、执行接口预留和持久化保持不变。

维护工具`python -m backend.planner.build_vd10_screen_data`只维护本批场景与引用，不新增元操作，不修改原能力语义。不得以流程需要某动作作为该动作已实现的证据。
