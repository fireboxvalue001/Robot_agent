# 编排草案默认参数

生成流程后展开“本次需要补充什么”，点击“填入编排草案默认值”。仅填入有配置且当前为空的字段，不覆盖用户填写内容。检查或修改后点击“应用已填写项并重新编排”。填入本身不会提交、调用模型或执行设备。

油脂抽提：原文有据的温度、恒重阈值等仍沿用文档参数。新增15项缺失参数的草案示例，包括加液量、加热条件、循环上限、检查间隔与等待时长。它们是供调试编排的数值，不是标准规定或实验安全建议；尤其加热温度、剂量、拆卸温度必须与设备和审核方法核对。

适用其他配置流程：在参数定义中添加 `draft_default` 和 `draft_default_note`，填写相同单位的值及来源说明。后端按该字段的类型、范围、整数要求和枚举验证，再由通用表单呈现。不按参数名猜值，也不自动选范围下限。样品静置流程已配置时长30秒和常规存放方式。

实测质量、实际对象标识、位置、布尔状态确认、方法审批不预设为已完成；结果计算需要真实数据。没有可靠配置的字段仍需用户补充，不会为消除提示而制造设备或测量结果。

通过按钮填入并提交的值在文本中带“【草案默认值】”标记，后端保留 `source=draft_default`，包括AI提取后。流程详情显示来源，顶部提示使用前核对；所有配置流程仍保持 `execution_allowed=false`，不会因填完数值自动批准方法或放行物理执行。

## 编排与物理确认分离

已登记、描述完整且与场景适用范围匹配的方法，不再仅因 `review_status=draft` 阻断逻辑编排；原始登记状态不变。未登记、不兼容、已否决或停用的方法仍不能用于通过编排检查。用户明确选择仅允许已批准知识的模式时，场景级知识准入限制仍有效。

方法适用性与标准核对保存在 `usage_prerequisites`，在输入区“流程使用前提与注意事项”中默认折叠展示，不作为待补参数。设备型号、加热条件、通风、反馈、停止接口与烘箱准入等保存在 `physical_requirements`，在物理可执行确认阶段默认折叠展示，状态保持 `pending`。

这些条件目前是供后续设备校验对接的结构化要求，不代表已实现现场自动检测；任何参数默认值、用户文字或编排通过结论都不会授权设备执行。原有拖曳操作卡片、循环与分支保持不变。
